# 答辩演示要点

## 1. 演示前准备

1. 在 IDEA 中运行后端配置 `后端服务_demo`：使用 H2 内存库，Flyway 自动执行迁移，端口 8090；启动日志会打印自动探测到的二维码公开地址（`http://<当前局域网IP>:5199`），并把前端开发服务器拉起在 `0.0.0.0:5199`。
2. 进入 `platform/前端应用_frontend`，首次执行 `npm install`，之后执行 `npm run dev`，浏览器打开 `http://localhost:5199`。
3. 使用演示账号登录，密码统一为 `123`：`admin`（基地管理员）、`operator`（操作员）、`quality`（质检员）、`coop`（合作运营）、`government`（监管）。
4. 演示数据无需额外准备：`demo` 配置每 15 秒自动注入一组温湿度、光照和土壤水分遥测，生产指挥页每 20 秒自动刷新并显示更新时间。环境周期存证为**手动触发**：`demo` 配置已关闭定时任务，只有点击“立即生成并存证”才会汇总当前遥测并上链。
5. 需要演示阈值告警时，把 `application-demo.yml` 的 `app.demo.telemetry.alert-demo` 改为 `true`（或临时加 JVM 参数 `-Dapp.demo.telemetry.alert-demo=true`），也可以运行 `platform/开发脚本_scripts/模拟设备_telemetry-simulator.ps1 -TriggerAlert`。
6. 需要展示真实上链时，先启动实训环境虚拟机里的 FISCO BCOS 四节点和链上适配服务，再执行 `platform/开发脚本_scripts/验证真实上链_real-chain-smoke-test.ps1` 确认链路可用（`GET /health` 应返回合约地址 `0xf7636483…e27b`）。不启动节点也能演示：链上状态会显示为待上链 `PENDING`，业务不受影响。
7. 演示控制指令闭环时，再启动物联网服务与设备模拟器：`java -jar platform/后端服务_backend/物联网服务_greenhouse-iot/target/greenhouse-iot-0.1.0-SNAPSHOT.jar`，另开一个窗口运行 `platform/开发脚本_scripts/模拟设备_command-simulator.ps1`。只启业务后端时，指令会停在 `CREATED`，超时后进入重试再置为 `FAILED`，可作为“设备离线”的反例演示。

## 2. 两分钟项目介绍

本项目面向寒旱区设施农业示范基地，解决环境数据分散、控制依赖人工、质量溯源链不完整和多村合作经营难统计的问题。系统以一条完整业务闭环为主线：传感器按周期采集环境数据，生成批量哈希并仅将根哈希上链；控制服务根据阈值策略驱动通风、保温、补光和灌溉；采收后录入检测报告并生成合格证；包装环节生成一物一码；消费者扫码后完成签名校验、链上查询和复制码识别；村集体和政府端查看投入、分红和监管指标。前端分为首页数字孪生、生产指挥、质量溯源、合作运营和治理决策五个入口，后端由业务服务、物联网接入服务和链上存证合约共同支撑。

## 3. 现场演示流程

**第 1 步｜首页数字孪生**

全屏三维园区展示多座温室，点击任意温室进入单棚视角；页面下方的可信存证说明“环境数据按周期生成哈希链、仅将根哈希写入联盟链”的口径。

**第 2 步｜生产指挥（核心）**

1. 环境摘要四项指标按阈值实时判定，显示正常 / 偏低 / 偏高 / 告警；顶部状态条随告警变为黄色或红色。
2. 点击任意指标卡打开阈值调节弹窗，可修改目标范围、告警范围、控制动作和自动联动开关；保存后卡片说明与状态立即按新阈值重算。
3. 出现偏离或告警时，点击命令条上的“阈值联动”：系统按各指标的 `control_action` 自动找到对应设备并下发指令（温度→通风、光照不足→补光、土壤偏低→灌溉）。指令先进入 `CREATED`，由物联网服务发布到设备命令主题并置为 `DISPATCHED`，设备回执后收敛为 `SUCCEEDED`；没有真实设备时用模拟器脚本回执。
4. 演示设备控制：切换循环风机、补光灯等开关，点击“立即通风”查看风机与卷帘机联动，执行今日水肥计划，导出环境周期 CSV。
5. 底部“周期根哈希”面板展示环境周期温度曲线、周期哈希链、最新根哈希、区块高度和联盟链回执状态；需要新增周期时点击面板右上角“立即生成并存证”，系统会把当前温度、湿度、光照、土壤水分四项遥测汇总并提交链上，不再由后台自动生成。

**第 3 步｜质量溯源**

1. 查询 `GH-TRACE-2026-0001`：展示链上核验印章、环境根哈希、签名公钥，以及环境周期、电子合格证、一物一码三张存证卡（含链上交易哈希）。
2. 展示哈希指针链：种植 → 农事 → 检测 → 合格证 → 包装共 5 个区块，每块显示本节点摘要与前序摘要；若某节点摘要被篡改，该块会标为“断链”并变红。
3. 切换“按田块编号”查询 `F-A-03`：以监管视角查看该田块的完整指针链、绑定产品编码和校验结论，说明同一批数据既能按码查、也能按地块查。
4. 追加追溯节点：在指针链面板选择阶段“运输”、填写节点说明后点“追加节点”，新节点会接在链尾并按顺序上链，区块上显示“链上 0x…”，说明追溯链不是只读的演示数据，业务写入会真正落链。
5. 模拟消费者扫码：点击“扫码验证”，第一次显示“首次验证通过”；再次扫码显示“重复扫码风险：该编码已被扫码 2 次”，同时该次数会进入治理页的重复扫码风险统计。
6. 电子合格证验签：点击“生成密钥并验签”，浏览器用 WebCrypto 生成 Ed25519 密钥并对 canonical 串签名，后端验签通过并写入验签流水；再点“篡改后验签”，同一份签名配上被改过的内容会返回“签名无效”，说明链上链下摘要为何能识别篡改。
7. 完成一次写操作：上传检测报告（自动计算 SHA-256）→ 备案电子合格证 → 生成一物一码。

**第 4 步｜合作运营**

展示合作村庄、入股土地、本期分红和平均股权四项指标，以及分红与股权分布图（待确认分红显示为琥珀色），再演示新增入股或分红方案。

**第 5 步｜治理决策**

展示接入温室、设备在线率、待处理预警和溯源覆盖率；风险预警的三项明细分别来自设备在线状态、环境周期链上状态和扫码风控记录，可说明“预警数字来自真实统计”。下方“最近预警”列出遥测超限时自动落库的记录，可现场点击“确认处理”，演示预警从产生到闭环的过程。

同一页的“链上存证”面板展示适配服务联通状态、合约地址和四类待补偿条数。想演示容错时：先关闭链节点或适配服务，再录入一条环境周期，页面会显示该周期待上链且待补偿数 +1；重新启动适配服务后点“立即补偿”，条数归零并写回真实交易哈希，可说明“链上失败不影响业务，恢复后自动补齐”。正常在线时该条数应为 0，补偿按钮处于“无待补偿存证”状态。

再往下是“外部平台对接”面板：列出京东农场、气象、短信三个适配器的模式（模拟适配 / 真实接口）、最近调用结果与累计成功失败次数，管理员可点“立即同步”跑一遍，下方留痕显示请求编号、尝试次数与耗时。演示时说明：外部接口用「接口 + mock/rest 双实现」隔离，默认 mock 不依赖外网；真实对接只改配置，且每次调用都留痕、失败会按 2 次重试后降级，不影响主业务。想看短信链路，直接把温度顶到告警上限以上（如 38.5℃），告警落库后会触发一条短信留痕。

## 4. 常见答辩问题

**为什么需要区块链，不用普通数据库行不行？**

普通数据库可以完成业务流程，但基地、村集体、质检机构、政府和消费者之间没有共同的信任中心。联盟链用于保存根哈希、溯源码摘要、合格证摘要和扫码记录，使关键字段可以被多方独立验证，同时避免把原始大文件和高频数据上链。

**原始数据篡改怎么办？**

原始数据虽然保存在链下，但每次核验都会重新计算周期摘要并与链上根哈希比较。只修改链下文件而不修改链上记录，会被立即识别；链上记录本身由多个节点共同维护。

**一物一码如何防复制？**

溯源码包含产品编码、生产商公钥标识和平台私钥签名。消费者扫码后先验证签名，再查询链上编码和扫码记录。编码不存在、签名错误或同一码短时间高频出现时，系统给出复制码风险。

**阈值是怎么判定和联动的？**

阈值保存在 `environment_threshold` 表，按温室和指标唯一，包含目标范围、告警范围、控制动作和启用状态。界面用同一份配置对实时值逐项判定：超出告警范围判为“告警”，落在告警范围内但偏离目标判为“偏低/偏高”，落在目标范围判为“正常”。命令条上的“阈值联动”把 `control_action` 映射成设备类型（通风→风机、补光→补光灯组、灌溉→水肥阀组、增湿→微雾、卷帘→卷帘机），在该温室里寻找在线设备并下发对应指令，收集回执后刷新设备状态；缺少对应设备时只提示缺少项，不会误发指令。

**实时值来自哪里，会不会和周期数据冲突？**

温室总览优先取该温室的最新设备遥测值，没有遥测时才回退到最近周期的聚合读数。周期数据继续负责趋势曲线、根哈希和链上存证，即“实时值看设备、历史与存证看周期”，两套口径互不覆盖。

**为什么没有把 MD5 作为唯一摘要？**

MD5 已经不适合作为抗碰撞的安全摘要。总体设计优先采用 SHA-256 或 SM3，MD5 只用于兼容无法修改的旧接口。

**项目最难的部分是什么？**

难点不是单个页面，而是把物联网采集、控制指令、链上根哈希、合格证和一物一码之间的关系保持一致，并处理设备离线、链上失败和业务回滚。

**智能合约编译和部署到什么程度了？**

合约已用 solc 0.8.26（optimizer 200 runs，EVM `istanbul`）编译通过：0 错误 0 警告、16 个外部函数、运行时代码 9434 字节，ABI 和字节码已输出到 `智能合约_contracts/`，可复现命令是 `开发脚本_scripts/编译智能合约_compile-contract.ps1`。合约已部署到实训环境的 FISCO BCOS 2.8.0 四节点链（群组 1），地址 `0xf763648341076819904e80d855127272f2d4e27b`，部署交易 `0x28b47e96…3e93f`，服务账户已通过 `setRole` 获得设备、质检和业务三个角色。

后端通过 `integration/chain/ChainGateway` 调用链上能力，提供两种实现：默认的 `RestChainGateway` 以 `{method, arguments}` 调用链上适配服务，由适配服务用 Java SDK 2.9.1 签名发交易，回执来自真实区块；`SimulatedChainGateway` 只在自动化测试中使用，按调用内容生成确定性哈希。环境周期入库、合格证备案、生成一物一码和消费者扫码都会把回执写回数据库（`chain_tx_hash` / `chain_status`），链上失败时由 `ChainInvoker` 保留 `PENDING` 待补偿状态而不回滚业务，随后由每 60 秒执行一次的 `ChainCompensationJob` 自动重试，也可以由管理员在治理驾驶舱点“立即补偿”手工触发。

答辩现场如果想展示链上核验，可以在实训环境虚拟机里用控制台执行 `./console.sh 1 getTransactionReceipt <交易哈希>`，回执中的 `from`、`to`、`status` 和事件日志可以作为交易真实落链的旁证；不想依赖节点时把 `CHAIN_MODE` 设为 `simulated` 即可。
