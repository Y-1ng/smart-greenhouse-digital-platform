# 需求分析

## 1. 项目定位

平台面向寒旱区设施农业示范基地，覆盖“环境采集—智能调控—水肥执行—作物档案—检测合格证—一物一码—消费者验证—合作运营”的完整业务链。项目重点是形成一条可演示、可测试、可解释的闭环，而不是一次性完成大型农业云平台的全部能力。

## 2. 用户角色

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| 基地管理员 | 维护基地、温室、人员和设备 | 全局配置与经营数据查看 |
| 温室操作员 | 执行环境控制与水肥计划 | 仅能操作授权温室 |
| 农技与巡检员 | 维护作物、农事和巡检档案 | 可录入，不可生成合格证 |
| 质检与合格证管理员 | 上传检测报告、生成合格证和溯源码 | 不可修改控制策略 |
| 村集体与合作社管理员 | 维护入股、合同、分红数据 | 仅查看本村和授权项目 |
| 政府监管人员 | 查看示范项目指标和预警 | 只读 |
| 消费者 | 扫码验证产品 | 仅查看公开溯源信息 |

## 3. 核心业务规则

- 同一温室在同一时间段只能有一个有效环境周期。
- 环境原始数据链下保存，链上只保存周期根哈希和必要元数据。
- 溯源码在平台内唯一，签名验证与链上记录查询必须同时执行。
- 控制指令使用唯一编号，重复提交不重复执行。
- 数据采集、控制、检测、赋码和分红确认均写入审计日志。
- 链上交易失败不得把业务状态直接标记为成功。
- 合格证摘要优先使用 SHA-256 或 SM3；MD5 只用于旧接口兼容。

## 4. 功能需求

| 编号 | 功能 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- | --- |
| FR-01 | 环境监测 | 温湿度、光照、CO₂、土壤水分 | 汇总周期、计算摘要 | 实时曲线与告警 |
| FR-02 | 智能调控 | 阈值、策略、操作者 | 生成设备指令 | 控制回执与执行记录 |
| FR-03 | 水肥一体 | 配方、计划、EC/pH | 计算用量、控制阀门泵 | 灌溉记录与异常报警 |
| FR-04 | 作物与农事 | 品种、定植、施肥、巡检 | 关联批次 | 作物档案与图片 |
| FR-05 | 检测与合格证 | 检测报告、证书信息 | 摘要计算与备案 | 合格证状态 |
| FR-06 | 一物一码 | 产品编码、批次、密钥 | 签名、赋码、验证 | 扫码结果与复制码提示 |
| FR-07 | 区块链存证 | 根哈希、批次、签名摘要 | 合约写入与查询 | 交易回执 |
| FR-08 | 合作运营 | 一村一图、股权、合同、分红 | 计算与确认 | 经营驾驶舱 |
| FR-09 | 外部平台接口 | 京东农场、气象、短信数据 | 适配和重试 | 同步状态 |
| FR-10 | 设备运维 | 在线状态、标定、故障 | 工单流转 | 运维记录 |

## 5. 非功能需求

- 安全：身份认证、RBAC、设备凭证、签名校验、密钥保护、审计日志。
- 性能：常用查询平均响应不超过 2 秒，实时数据延迟不超过 10 秒。
- 可靠性：接口幂等、链上失败补偿、离线数据补传。
- 易用性：大屏、电脑和移动端均可访问，异常给出明确原因。
- 可维护性：模块分层，接口配置化，避免把业务规则写死在页面。

## 6. 验收主流程

模拟一个温室完成环境采集、根哈希上链和一次自动控制；按水肥计划执行一次灌溉；录入一次检测报告并生成合格证；为产品批次生成一物一码；消费者扫码后完成签名验证和链上查询；最后在合作运营驾驶舱展示村集体投入与收益统计。
